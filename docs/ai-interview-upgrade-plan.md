# AI 面试系统优化改造实施方案

> 版本：v1.0　编制日期：2026-10-25
> 适用范围：`edu-ai-path-master` 现有 AI 面试官（`/ai-interview`）与存量模拟面试（`/mock-interview`）
> 编制依据：当前代码（`AiInterviewServiceImpl`、`AiInterview.vue`、`interview_question` 表）+ BOSS 直聘 AI 模拟面试公开资料
> 排期口径：1 人全职、约 6 小时/天；兼职投入按比例顺延

---

## 0. 执行摘要

**一句话结论**：现有系统已经跑通"配置 → 多轮问答 → 异步报告"的闭环，但本质是"随机抽题 + 单个大模型自由对话"，距离 BOSS 直聘"岗位适配 + 结构化考察 + 可复盘报告"还有三个代差：**题库太薄、评分太粗、报告不可留存**。

**改造主线（按投入产出排序）**：

1. **先补"题"和"评"**（P0，3 周）：题库结构化扩量 → 面试蓝图 → 逐轮评分 → 报告落库。做完这一步，系统从"能聊"变成"像面试"。
2. **再做"岗位适配"和"语音"**（P1，3 周）：JD/岗位画像驱动出题、追问深度控制、ASR 语音作答、复盘报告增强。
3. **最后做"体验与运营"**（P2，2 周）：计时/断线恢复/免费首场/多面试官人格/数据看板。

**总周期**：约 8 周（42 人日，含 20% 缓冲）。
**最小可用版本（MVP）**：3 周（阶段 0-2，18 人日），即可支撑答辩演示与真实使用。

**不可行项**：微表情/情绪识别、实时视频面试、端到端语音对话、爬取平台岗位数据、宣称与真人评分一致率等 10 项，详见第 6 节。

## 1. 现状盘点（基于代码事实，非推测）

| 模块 | 现状 | 代码/数据证据 |
|---|---|---|
| 面试流程 | 配置方向/难度/轮数/个性化 → 开始（固定开场白 + 随机真题，秒开）→ 逐轮问答 → 手动或 AI 自动结束 → 异步生成报告 → 结果页 | `AiInterviewServiceImpl.start/answer/finish/getReport` |
| 会话存储 | Redis `aiinterview:session:{id}`，TTL **2 小时**；**不落 MySQL** | `SESSION_TTL = Duration.ofHours(2)` |
| 题库 | **仅 12 道已审核题**：Java 困难 6、Java 中等 2、前端简单 2、算法中等 2；**大数据/运维/测试 0 题** | `SELECT COUNT(*) FROM interview_question WHERE status='approved'` |
| 题目结构 | 只有 `question_content` + `reference_answer`；**无知识点、无考察点、无题型、无权重** | `DESCRIBE interview_question` |
| 提问逻辑 | 随机抽题 + LLM 自由决定"追问或换题"；无面试蓝图、无追问层级控制 | `buildTurnPrompt` + `pickRealQuestion` |
| 评分 | **只在面试结束后调 1 次 LLM**，产出总分 + 5 个能力分；无逐轮评分、无证据引用 | `buildFinishPrompt` |
| 评分兜底 | LLM 不可用时按"完成轮数"给分：`50 + 完成率×30`，与回答质量无关 | `localScore()` |
| 报告 | 仅存 Redis，2 小时后丢失；**无历史列表、无回放、无成长趋势** | `buildReportData` + Redis TTL |
| 实时反馈 | 每轮只有一句 ≤80 字点评，无维度分、无改进动作 | `buildTurnPrompt` 的 `comment` |
| 语音 | AI 面试**纯文本**；存量 MockInterview 有 MediaRecorder 录音，但**只生成本地 blob，从未上传/转写** | `MockInterview.vue` 第 415 行注释"这里应该上传到服务器"；`AiInterview.vue` 无任何语音 API |
| 计费 | 每场固定 10 积分，无免费体验；中途失败不退款 | `AI_INTERVIEW_COST = 10` |
| 存量模块 | `mock_interview` / `mock_interview_answer` 已落库，支持逐题四维评分，但语音同样未打通；`interview_evaluation` 仅有实体/Mapper，**无业务调用** | 表数据：6 场面试、5 条回答 |
| 岗位适配 | 无简历、无 JD、无岗位画像，仅"技术方向 + 难度"三档 | 全库无 Resume/Job/Position 实体 |

**结论**：当前系统是"Demo 级可用、产品级不足"。最致命的不是交互，而是**内容供给（12 题）**和**评价可信度（单次 LLM 打分）**。

## 2. BOSS 直聘 AI 模拟面试对标拆解

> 说明：以下基于公开报道与产品可见信息；**具体评分权重、Prompt、模型属于平台商业机密，无法也不应照搬**，我们只复用交互与信息架构。

### 2.1 四层能力模型

| 层 | BOSS 直聘公开表现 | 可复用设计要点 |
|---|---|---|
| **岗位层** | 用户输入**目标岗位**，题目精准适配岗位需求；依托平台海量真实岗位数据 | 用"岗位画像（技能关键词 + 考察维度 + 职级）"驱动出题与加权，而不是只选"Java/前端" |
| **对话层** | AI 模拟面试官一对一对话；根据回答深度追问；高度还原真实面试场景 | 结构化蓝图（维度×轮次×难度）+ 自适应追问（1-3 层，有上限）；固定节奏而非随机跳题 |
| **评价层** | 实时反馈"应答逻辑、表达流畅度"；面试后生成专业报告 | **逐轮轻量反馈**（维度分 + 一句可执行建议）+ 终局报告；评分要有证据、可解释 |
| **复盘层** | 报告可回看表现；提供"题目考察点"与"思路参考" | 每题四段式：考察点 / 思路参考 / 我的回答 / 差距；支持回放与再练 |

### 2.2 交互逻辑（可复用的 6 个动作）

1. **低门槛启动**：选目标岗位（或粘贴 JD）→ 直接开始，不需要填长表单。
2. **新手免费体验**：首场免费/真题演练，降低首次付费门槛。
3. **一题一答 + 即时反馈**：每答完一题，先给"逻辑/表达"的短反馈，再进入下一题。
4. **自适应追问**：回答浅 → 追问细节；回答有项目证据 → 深挖技术选型；答不上 → 降难度换题。
5. **进度感**：轮次进度、剩余时间、当前考察维度可见。
6. **结束后一键复盘**：报告即"练习工具"，可跳转学习路径/专项练习。

### 2.3 评分机制（行业通用做法 + 我们的落地口径）

BOSS 直聘未公开权重。行业可验证的做法是 **"维度 × 权重 × 行为证据"**：

- 维度建议：`技术准确性 35%`、`逻辑结构 25%`、`表达清晰 20%`、`岗位匹配 20%`。
- 每个维度 0-100，必须有 **行为锚点**（例如逻辑 80 分 = "结论先行 + 分点论证 + 有取舍理由"）。
- 每条评分必须引用候选人原话作为 **evidence**，否则视为无效评分。
- 单轮分按蓝图权重加权；总分 = 各轮加权平均 − 未完成轮次扣分。
- **禁止**用回答长度、关键词命中数直接当分数（可作辅助信号，不可作主分）。

### 2.4 用户体验要点

- 场景还原：面试官头像/语音、正式开场、结束语、计时。
- 反馈即时：不要等 60 秒报告才给任何反馈。
- 报告可带走：历史记录、成长曲线、可回看。
- 失败可恢复：断网/刷新后能回到当前轮次（我们有 Redis 会话但前端无恢复入口）。

## 4. 整体改造路线图

| 阶段 | 周期 | 目标 | 核心交付物 | 验收标准 |
|---|---|---|---|---|
| **阶段 0 基线固化** | 第 1 周（3 人日） | 把现状变成可回归的基线 | ① 面试链路埋点（开始/轮次/结束/报告耗时、失败率）② 现有 12 题标注知识点/难度 ③ 5 份基准面试录像/文本样本 | 能复现 3 类问题：抽题重复、报告丢失、评分波动；基线指标可查询 |
| **阶段 1 题库与蓝图** | 第 2-3 周（8 人日） | 解决"没题、乱题" | ① `interview_question` 扩字段（知识点/题型/考察点/权重/来源/审核状态）② 8 方向 × 3 难度 × ≥5 题（≥120 题，LLM 生成 + 人工审核）③ `interview_blueprint` 表 + 选题器 ④ 管理端题库审核页 | 8 方向均有题；同一场面试题目不重复率 ≥95%；蓝图覆盖 4 个维度 |
| **阶段 2 逐轮评分与追问** | 第 3-4 周（7 人日） | 从"聊天"变"面试" | ① 每轮评分 JSON（4 维 + evidence + 建议）② 追问层级控制（最多 2 层）③ 前端逐轮反馈卡片 ④ JSON schema 校验 + 1 次重试 | 每轮都有 4 维分与证据；P95 响应 <6s（文本）；解析成功率 ≥99% |
| **阶段 3 报告落库与复盘** | 第 5 周（6 人日） | 报告可留存、可回看 | ① `ai_interview` / `ai_interview_round` / `ai_interview_report` 三表 ② 历史列表 + 详情回放 ③ 报告四段式（考察点/思路/我的回答/差距）④ 雷达图 | 刷新/隔天仍可查看报告；报告覆盖 100% 轮次；历史分页可用 |
| **阶段 4 语音作答** | 第 6-7 周（8 人日，可选） | 提升沉浸感与表达维度 | ① 录音上传接口 + 对象存储 ② DashScope ASR 转写 ③ 可选 TTS 播报题目 ④ 表达流畅度指标（语速/停顿） | 30 秒内录音转写成功率 ≥95%；转写文本可直接进入现有评分链路 |
| **阶段 5 体验与运营** | 第 7-8 周（6 人日） | 提升完成率与复购 | ① 计时/进度 ② 断线恢复 ③ 免费首场 ④ 失败自动退积分 ⑤ 多面试官人格（技术/HR）⑥ 数据看板 | 完成率提升 ≥20%；报告查看率 ≥80%；失败退款 100% |
| **阶段 6 压测与验收** | 第 8 周（4 人日） | 稳定交付 | 压测报告、故障演练、验收清单、上线开关 | 20 并发无超时；LLM 故障可降级；指标达标 |

> 关键路径：阶段 1 → 阶段 2 → 阶段 3。阶段 4（语音）可独立延后，不影响主线交付。

## 6. 不可行项说明（技术/数据/合规/成本四维）

| # | 不可行方向 | 具体原因 | 替代方案 |
|---|---|---|---|
| 1 | **微表情、情绪、眼动、测谎式判断** | ① 生物识别信息属敏感个人信息，需单独同意与高等级保护；② 就业场景使用可能构成歧视；③ 需专用 CV 模型与摄像头采集，误判率高、无标注数据；④ 与"练习工具"定位冲突 | 不做情绪判断；只做"语速/停顿/口头禅"等可解释的表达指标 |
| 2 | **实时视频面试（WebRTC 双/单向）** | 需 TURN/SFU 媒体服务器、带宽与录制存储；当前无媒体服务；隐私合规成本高；收益低 | 纯音频或文本面试；录制仅本地预览 |
| 3 | **端到端实时语音对话（speech-to-speech）** | 需 Realtime API / WebSocket 音频流、回声消除、打断（barge-in）、低延迟；当前仅接入 ChatLanguageModel + EmbeddingModel，无音频通道；成本与工程复杂度远超课程项目 | 半双工：录音 → ASR → 文本 → LLM → TTS |
| 4 | **自动爬取 BOSS 直聘岗位/题库** | 违反平台协议与 robots；法律与封禁风险；数据不可授权 | 用户手动粘贴 JD；使用公开岗位模板库 |
| 5 | **全自动简历解析（PDF/图片）** | 需 OCR/版面分析；简历含身份证/电话等 PII，需加密与最小化；无授权数据源 | 用户粘贴纯文本简历；只抽取技能关键词 |
| 6 | **宣称"与真人面试官评分一致率 90%"** | 需专家标注数据集、信效度检验、跨岗位校准；我们无标注数据与专家资源；此类宣称属虚假宣传风险 | 明确标注"AI 练习参考分，不构成招聘评价" |
| 7 | **无限轮/长会话面试** | 每轮全量历史进 prompt，token 与延迟线性增长；Redis TTL 2h；无流式；成本不可控 | 限制 6-12 轮；摘要压缩历史 |
| 8 | **报告同步即时生成（0 秒）** | 单次报告 LLM 需 30-60 秒；同步会阻塞请求；当前无 SSE | 异步 + 轮询（已有）；后续可加 SSE |
| 9 | **本地大模型/离线部署** | 需 GPU、模型运维、量化与并发调优；当前全部走百炼 API | 继续用 DashScope，按量付费 |
| 10 | **AI 分数直接用于招聘决策** | 合规与责任问题（自动化决策、申诉机制、就业歧视）；产品定位是练习 | 仅作学习反馈；报告显著标注"非招聘依据" |
| 11 | **跨设备实时同步/多端同面** | 需 WebSocket/推送与分布式会话；非核心场景 | 单端面试 + Redis 断线恢复 |

### 7.2 API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/ai-interview/start` | 入参新增 `level`、`jobProfile`（可选）、`answerMode`；返回蓝图摘要与第一题 |
| POST | `/api/ai-interview/answer` | 入参新增 `answerMode`、`audioId`；返回**本轮评分** + 下一题 |
| GET | `/api/ai-interview/{id}/state` | 断线恢复：当前轮次、题目、已答轮次 |
| POST | `/api/ai-interview/{id}/finish` | 幂等结束，异步报告 |
| GET | `/api/ai-interview/{id}/report` | 轮询报告（保留） |
| GET | `/api/ai-interview/history` | 历史列表（分页） |
| POST | `/api/ai-interview/audio` | 上传录音，返回 `audioId`/URL |
| GET | `/api/ai-interview/blueprints` | 按方向/职级获取蓝图（前端展示考察范围） |

### 7.3 评分 Rubric（固定，避免模型漂移）

| 维度 | 权重 | 80 分锚点（示例） | 60 分锚点 | 40 分锚点 |
|---|---|---|---|---|
| 技术准确性 | 35% | 概念准确、边界清晰、能说清原理与取舍 | 主干正确，细节有误 | 关键概念错误 |
| 逻辑结构 | 25% | 结论先行、分点论证、有因果与取舍 | 有结构但层次混乱 | 想到哪说到哪 |
| 表达清晰 | 20% | 术语准确、句子完整、无大量口头禅 | 能听懂但啰嗦 | 难以理解 |
| 岗位匹配 | 20% | 回答贴合目标岗位职责与职级要求 | 部分相关 | 跑题 |

约束：
- 每条评分必须带 `evidence`（候选人原话片段），否则该维度记 0。
- 单轮分数 = Σ(维度分×权重)。
- 总分 = 各轮加权平均；未完成轮次按 0 计入分母并扣 5-10 分。
- LLM 解析失败 → 该轮标"未评分"，报告标 `degraded=1`，不伪造分数。

### 7.4 Prompt 改造要点

1. **系统角色固定**："资深<方向>面试官，职级<level>，按蓝图提问"。
2. **输入结构化**：蓝图（维度/轮次/难度）+ 岗位画像 + 上一轮评分 + 追问层级。
3. **输出强约束 JSON**：`{comment, question, dimension, followUpLevel, ended, scores:{...}, evidence:[...]}`。
4. **防重复**：把已问题目列表放入 prompt，并要求"不得与已问题目重复"。
5. **防幻觉**：只允许从候选题库选题；追问可生成，但不得编造企业/项目事实。
6. **长度控制**：点评 ≤80 字，题目 ≤70 字，避免报告式长文。

### 7.5 语音链路（半双工，可行）

```
浏览器 MediaRecorder(webm/opus)
  → POST /api/ai-interview/audio（限 60s、≤5MB）
  → 对象存储/MinIO（私有桶，按用户隔离）
  → DashScope ASR（Paraformer 录音文件识别）
  → 文本写入 ai_interview_round.user_answer
  → 进入现有评分链路（文本）
  → 可选 TTS（CosyVoice）播报下一题
```

成本控制：仅上传压缩音频；转写失败降级为"请改用文字作答"；音频默认 7 天过期。

### 7.6 成本估算（按 10 轮/场）

| 项 | 估算 |
|---|---|
| 每轮 LLM（输入≈1.5k tokens，输出≈300 tokens） | 10 轮 ≈ 18k tokens |
| 报告 LLM（输入≈3k，输出≈1.5k） | ≈ 4.5k tokens |
| 单场合计 | ≈ 22.5k tokens（不含 ASR/TTS） |
| 10 积分定价 | 需保证积分单价 ≥ 模型成本 × 2（含失败重试） |
| ASR（若开） | 按 10 分钟音频估算，单独计价或提高场次积分 |

> 建议：语音场次单独定价（如 15 积分），避免语音成本侵蚀利润。

## 8. 验收指标与风险

### 8.1 验收指标

| 指标 | 目标 |
|---|---|
| 题库覆盖 | 8 方向 × 3 难度，每格 ≥5 题 |
| 同场题目重复率 | ≤5% |
| 逐轮评分覆盖率 | 100%（每轮 4 维 + evidence） |
| JSON 解析成功率 | ≥99%（含 1 次重试） |
| 文本答题 P95 延迟 | <6 秒 |
| 报告生成 P95 | <60 秒 |
| 报告可查看时长 | ≥永久（落库），Redis 仅会话 |
| LLM 故障降级 | 100% 可用，报告标注"降级" |
| 完成率 | 较基线 +20% |
| 失败退款 | 100% 自动退 |

### 8.2 主要风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 评分漂移 | 同一回答分数波动 | 固定 rubric + few-shot + 温度 0.2 + 二次校验 |
| 题库内容质量 | 错题/幻觉题伤害体验 | LLM 生成 + 人工审核 + 上线前抽检 20% |
| 音频隐私 | 合规风险 | 明示授权、私有存储、7 天过期、可删除 |
| 报告丢失 | 用户投诉 | 三表落库 + 生成失败可重试 + 幂等 |
| 并发/超时 | 面试中断 | 线程池隔离、超时降级、Redis 会话恢复 |
| 成本失控 | 积分亏损 | 轮数上限、历史摘要压缩、按场次定价 |
